# Модуль 5 — Возможности агентов для программирования: MCP, навыки, плагины и собственные агенты

[Оригинал материала](https://github.com/Gordondalos/ai-dev-tools-zoomcamp/blob/b47dff65161c878d095e288e9f9e5b907f5aa3c6/05-agent-capabilities/README.md)

<a id="overview"></a>

## Обзор

Этот модуль посвящён тому, как расширять, настраивать, ограничивать и проверять современных агентов для программирования, а также делиться их конфигурациями.

Он не посвящён одному конкретному инструменту программирования. В примерах может использоваться определённая среда, но концепции должны быть переносимы между современными агентными системами разработки, такими как Claude Code, Codex, OpenCode, Cursor, GitHub Copilot, Aider, Windsurf, и будущими инструментами.

Устойчивая концептуальная модель:

```text
instructions
context
tools
permissions
reusable workflows
specialized agents
packaging and sharing
custom agent loops
audit trail
```

Перевод списка:

> - Инструкции
> - Контекст
> - Инструменты
> - Разрешения
> - Повторно используемые рабочие процессы
> - Специализированные агенты
> - Упаковка и распространение
> - Собственные циклы работы агентов
> - Журнал действий для аудита

В разных продуктах эти возможности называются по-разному. Например, один инструмент может называть повторно используемый рабочий процесс навыком, а другой — командой, промптом, правилом, рецептом или расширением. Курс должен сначала объяснять саму возможность, а уже затем — синтаксис конкретного продукта.

Вы научитесь:

- Понимать цикл работы агента: сбор контекста, планирование, вызовы инструментов, правки, тесты и итерации до получения diff или PR. Для этого вы направите агента на приложение из модуля 2/3 и поручите ему спланировать и реализовать небольшую функцию
- Писать переносимые инструкции проекта (AGENTS.md, CLAUDE.md или аналог), описывающие архитектуру, команды, соглашения и границы безопасности, чтобы ими мог пользоваться любой агент
- С помощью MCP предоставлять агенту ограниченный набор инструментов, ресурсов и промптов вместо доступа ко всему сразу
- Превращать регулярно повторяемый чек-лист или процедуру в повторно используемый рабочий процесс: навык, slash-команду, правило или рецепт в зависимости от инструмента
- Добавлять хуки и защитные ограничения, чтобы форматирование, линтинг и проверки безопасности выполнялись автоматически, а не зависели от просьбы «пожалуйста, будь осторожен»
- Создавать специализированных субагентов с ограниченным контекстом и разрешениями для вспомогательных задач, таких как проверка API, отладка или тестирование
- Упаковывать общую конфигурацию в плагин или расширение, когда её нужно переносить между командами или проектами, а не просто хранить в одном репозитории
- Определять, когда для CI/CD, задач по расписанию или структурированных конвейеров стоит создать собственного агента вместо использования интерактивного агента для программирования

Краткое содержание модуля: сопроводительная статья рассматривает два строительных блока для работы с агентами для программирования: повторно используемые навыки для регулярно выполняемых процедур и специализированные субагенты, работающие в собственном изолированном контексте, чтобы не засорять основной сеанс. В ней показано, как совместить оба подхода с git worktrees, чтобы несколько агентов параллельно выполняли отдельные задачи, а основной сеанс выступал оркестратором, следующим определённому процессу.

[Читать статью: «Строительные блоки агентов для программирования: повторно используемые навыки и специализированные субагенты»](https://aishippingblog.com/p/coding-agent-building-blocks-reusable)

## Результат работы по модулю: набор расширений агента

Студенты дополняют приложение из модулей 2 и 3 набором расширений агента.

Минимальные требования:

```text
1 project instructions file
1 reusable workflow/skill/command
1 specialized subagent
1 MCP tool/server
1 hook or guardrail
1 small plugin/extension package OR custom agent
1 permission/security note
```

Перевод списка:

> - 1 файл с инструкциями проекта
> - 1 повторно используемый рабочий процесс, навык или команда
> - 1 специализированный субагент
> - 1 инструмент или сервер MCP
> - 1 хук или защитное ограничение
> - 1 небольшой пакет плагина или расширения ЛИБО собственный агент
> - 1 заметка о разрешениях и безопасности

Предлагаемая структура репозитория:

```text
AGENTS.md
CLAUDE.md or equivalent tool-specific instructions

agent-capabilities/
  review-api-change/
  debug-ci-failure/
  subagents/

agent-hooks/

mcp-server/
  server.py
  README.md

plugins/
  ai-devtools-agent-pack/

custom-agent/
  agent.py
  README.md

docs/
  agent-extension-pack.md
  permissions.md
  demo.md
```

Примечание: `or equivalent tool-specific instructions` означает «или аналогичные инструкции для конкретного инструмента». Имена файлов и каталогов в примере сохранены без изменений.

Сценарий демонстрации:

1. Агент читает инструкции проекта.
2. Запускается повторно используемый рабочий процесс.
3. Специализированный субагент проверяет изменение API.
4. Агент вызывает инструмент MCP.
5. Хук или защитное ограничение блокирует действие, выполняет форматирование, проверку или запись в журнал.
6. Студент просматривает итоговый diff.
