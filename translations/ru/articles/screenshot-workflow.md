# Создание обрезанных скриншотов веб-страниц для статей

Скриншоты в статье должны показывать ту часть страницы, которая подкрепляет окружающий текст. Полное окно браузера обычно добавляет навигацию, пустое пространство и постороннее содержимое. Сделайте снимок страницы с заданными размерами, а затем оставьте только нужную панель.

Для каждого скриншота придерживайтесь одной и той же последовательности:

1. Представьте предмет иллюстрации в статье.
2. Сделайте снимок отрисованной страницы без элементов интерфейса браузера.
3. Обрежьте изображение до подтверждения, которое нужно читателю, оставив вокруг него достаточные поля.
4. Сохраните его в `articles/images/` с номером статьи в качестве префикса.
5. Вставьте `<figure>` сразу после текста, который изображение подкрепляет.
6. Добавьте содержательный альтернативный текст и отдельный вывод в `<figcaption>`.

Мы используем Chromium без графического интерфейса для снимков страниц и ImageMagick или Playwright для обрезки.

## Установите инструменты

Вам понадобятся:

- Chromium или Chrome
- ImageMagick для обрезки по координатам
- Playwright для обрезки по элементам

Проверьте, какие команды доступны на вашем компьютере:

```bash
command -v chromium
command -v convert
command -v identify
```

Для единообразия в этих примерах используются:

- `chromium`
- `convert`
- `identify`

В вашем дистрибутиве вместо них могут быть `chromium-browser` и подкоманды `magick`.

## Спланируйте иллюстрацию до создания снимка

Выбирайте область обрезки исходя из утверждения, которое подкрепляет иллюстрация:

- На скриншоте регистрации нужны название курса, статус и дата начала. Страница пустых полей формы на нём не нужна.
- На скриншоте репозитория нужны название репозитория, важные папки и описание. Общая верхняя панель GitHub на нём не нужна.
- На скриншоте программы курса нужен список модулей. Боковая панель документации и нижний колонтитул на нём не нужны.

Для скриншотов в статье выбирайте широкую область просмотра. Ширина от 1400 до 1600 пикселей даёт достаточно места для текста и панелей, расположенных рядом. Обрежьте результат примерно до 1200–1600 пикселей по ширине, чтобы он оставался читаемым при уменьшении в статье.

Итоговая обрезка должна подтверждать или пояснять предшествующий текст. Она не должна вводить тему, которая ещё не упоминалась в статье.

Оставьте вокруг нужного содержимого примерно 20–40 пикселей свободного пространства. Если содержимое находится внутри карточки или таблицы, сохраните пустое пространство снаружи всей рамки, а не прижимайте рамку к краю изображения. Заканчивайте обрезку таблицы после целой строки и её нижней линии. Не обрезайте следующую строку посередине.

## Сделайте снимок в Chromium и обрежьте его в ImageMagick

Используйте этот способ, когда нужное содержимое занимает прямоугольную область отрисованной страницы.

Создайте временную папку, а затем сделайте снимок отрисованной страницы без элементов управления браузером и полос прокрутки:

```bash
shot_dir="$(mktemp -d)"

chromium \
  --headless \
  --disable-gpu \
  --hide-scrollbars \
  --window-size=1600,1000 \
  --virtual-time-budget=8000 \
  --screenshot="$shot_dir/page.png" \
  'https://github.com/DataTalksClub/ai-dev-tools-zoomcamp'
```

`--window-size` управляет компоновкой страницы, а `--virtual-time-budget=8000` даёт клиентскому содержимому время отрисоваться до того, как Chromium сделает скриншот. Без ожидания GitHub может оставить заглушки загрузки в списке файлов.

Посмотрите на исходное изображение и выберите прямоугольник обрезки:

```bash
identify "$shot_dir/page.png"

convert "$shot_dir/page.png" \
  -crop 1540x480+30+78 \
  +repage \
  articles/images/06-course-repository.png
```

Параметры обрезки ImageMagick читаются как `WIDTHxHEIGHT+X+Y`:

- `1540x480` — итоговая ширина и высота.
- `+30+78` задаёт начало обрезки в 30 пикселях от левого края и 78 пикселях от верхнего.
- `+repage` удаляет из PNG смещение относительно исходного холста.

Используйте больший масштаб устройства, когда мелкому тексту требуется больше пикселей:

```bash
chromium \
  --headless \
  --disable-gpu \
  --hide-scrollbars \
  --force-device-scale-factor=1.25 \
  --window-size=1440,1900 \
  --screenshot="$shot_dir/page-125.png" \
  'https://courses.datatalks.club/ai-dev-tools-2026/'

convert "$shot_dir/page-125.png" \
  -crop 1200x495+300+680 \
  +repage \
  articles/images/06-course-platform.png
```

Масштаб 1,25 превращает область просмотра 1440 на 1900 CSS-пикселей в исходное изображение размером 1800 на 2375 пикселей. Измеряйте координаты обрезки по исходному PNG, а не по области просмотра в CSS.

## Сделайте снимок элемента с помощью Playwright

Используйте Playwright, когда содержимое можно найти с помощью устойчивого CSS-селектора. Playwright может вычислять координаты страницы во время выполнения, что избавляет от необходимости поддерживать жёстко заданные смещения обрезки.

Следующий скрипт делает снимок элемента `<main>` документации до конца описания модуля 5:

```python
from playwright.sync_api import sync_playwright

url = "https://datatalks.club/docs/courses/ai-dev-tools-zoomcamp/curriculum/"
output = "articles/images/06-course-docs.png"

with sync_playwright() as playwright:
    browser = playwright.chromium.launch(headless=True)
    page = browser.new_page(
        viewport={"width": 1600, "height": 1300},
        device_scale_factor=2,
        color_scheme="light",
    )
    page.goto(url, wait_until="networkidle")

    main = page.locator("main").bounding_box()
    module_5_bottom = page.locator(
        'main a[href*="05-agent-capabilities"]'
    ).evaluate(
        "element => "
        "element.parentElement.nextElementSibling.getBoundingClientRect().bottom"
    )

    padding = 32

    clip = {
        "x": main["x"] - padding,
        "y": main["y"] - padding,
        "width": main["width"] + 2 * padding,
        "height": module_5_bottom - main["y"] + 2 * padding,
    }

    page.screenshot(
        path=output,
        clip=clip,
        animations="disabled",
    )
    browser.close()
```

Запустите его в окружении, где доступен Playwright:

```bash
uv run --with playwright python capture_screenshot.py
```

Если один элемент содержит ровно то, что вам нужно, используйте вместо этого `locator.screenshot(path=...)`. Вычисляйте собственный `clip`, если скриншот должен начинаться с одного элемента и заканчиваться другим.

## Проверьте готовое изображение

Откройте PNG в исходном разрешении и проверьте каждый пункт:

- текст полностью загрузился
- никакие меню, баннеры cookie и элементы управления браузером не перекрывают содержимое
- ни один заголовок или край панели не обрезан
- снаружи всех видимых рамок карточек и таблиц есть свободное пространство
- таблицы заканчиваются после целой строки, а не посередине
- пустые формы и посторонняя навигация удалены
- в обрезанном изображении достаточно контекста, чтобы понять его смысл
- изображение остаётся читаемым при той ширине, с которой оно отображается в статье

Проверьте размеры и тип файла:

```bash
identify articles/images/06-course-repository.png
file articles/images/06-course-repository.png
```

Если на странице всё ещё видны заглушки загрузки, сделайте новый снимок с большим бюджетом виртуального времени или дождитесь появления определённого элемента в Playwright.

## Добавьте иллюстрацию в статью

Размещайте каждый скриншот сразу после абзаца, списка или примера, который он подкрепляет.

Используйте такой порядок:

```text
introductory text → figure → next paragraph or heading
```

Перевод: «Вводный текст → иллюстрация → следующий абзац или заголовок».

Текст представляет тему, иллюстрация даёт наглядное подтверждение, после чего статья продолжается. Не помещайте иллюстрацию сразу после заголовка без поясняющего текста. Если скриншот иллюстрирует список, помещайте его после списка, а не между заголовком и списком.

Используйте семантическую HTML-разметку из других статей курса:

```html
<figure>
  <img src="images/06-course-repository.png" alt="The AI Dev Tools Zoomcamp repository shows the five course module folders">
  <figcaption>The repository organizes the current course into five module folders</figcaption>
</figure>
```

Перевод альтернативного текста (`alt`): «В репозитории AI Dev Tools Zoomcamp показаны папки пяти модулей курса».

Перевод подписи (`figcaption`): «В репозитории материалы текущего курса распределены по пяти папкам модулей».

Сохраните относительный путь к изображению в элементе `<img>`. Альтернативный текст описывает изображение для тех, кто не может его увидеть. Подпись формулирует мысль, которую читатель должен извлечь из изображения. Не используйте одно и то же предложение для обоих элементов и не пишите альтернативный текст вроде «скриншот веб-сайта».

Не заменяйте иллюстрацию центрированным `<p>`, содержащим только изображение. `<figure>` и `<figcaption>` сохраняют связь между изображением и его подписью. Не собирайте несколько скриншотов в конце раздела, если каждый из них подкрепляет отдельный абзац.

## Назовите изображение

Добавляйте номер статьи в начало имени изображения, чтобы связанные файлы оставались рядом:

```text
articles/images/06-course-platform.png
articles/images/06-course-repository.png
articles/images/06-course-docs.png
```

Перед созданием коммита выполните:

```bash
git diff --check
git status --short
```

Убедитесь, что в коммит включены файл Markdown и все изображения, на которые он ссылается.
