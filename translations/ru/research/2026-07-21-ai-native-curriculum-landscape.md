<a id="headline-finding"></a>
## Главный вывод

Область сошлась на общей основе, которая **не** является классификацией инструментов. Это *управляемая сессия*: направлять → настраивать → автоматизировать → проверять.

Anthropic использует эти четыре глагола буквально как заголовки модулей верхнего уровня. Слоган страницы, перевод:

> Проводите длительные сессии Claude Code без постоянного вмешательства, которым можно доверять: направляйте, настраивайте, автоматизируйте и проверяйте.

Оригинал, дословно:

> Run long, hands-off Claude Code sessions you can trust: steer,
> configure, automate, and verify

Целевая аудитория, перевод: «Разработчики, которые уже используют Claude Code для отдельных запросов и хотят перейти к более длительным рабочим процессам с меньшим надзором в масштабе всей команды».

Оригинал, дословно: "Developers who already use Claude Code for single prompts and want to move to longer, less supervised, team-wide workflows."

**Важная оговорка по итогам проверки:** Anthropic не сравнивает инструменты, потому что это продуктовый курс одного поставщика, **а не** потому, что сравнение устарело. Не ссылайтесь на него как на основание удалить раздел сравнения. Stanford сохраняет IDE (Неделя 3) и терминал (Неделя 5) как отдельные недели с отдельными заданиями: сравнение остаётся вспомогательным материалом, а не основой структуры.

<a id="confirmed-findings"></a>
## Подтверждённые выводы

<a id="1-session-steering-is-taught-as-named-mechanics-high-confidence"></a>
### 1. Управление сессией преподаётся как набор конкретных приёмов (высокая уверенность)

Это не абстрактный «цикл разработки с ИИ». Цель модуля Anthropic «Направляйте работу» ("Steer the Work"), перевод:

> Определять объём работы в режиме планирования, управлять сжатием контекста так, чтобы сводки сохраняли важное, использовать меню отката для корректировки курса и выбирать между непосредственным управлением и автономными запусками по цели и по циклу.

Оригинал, дословно:

> scope work with plan mode, direct compaction so summaries keep what
> matters, use the rewind menu to course-correct, and choose between
> hands-on steering and autonomous goal and loop runs

Название урока: «Управление длительными сессиями» ("Steering Long Sessions").

> [!NOTE]
> Зеркало этого курса на Coursera представляет собой **более раннюю редакцию** (модули: «Что такое Claude Code?» / «Переходим к практике» / «Хуки и SDK» / «Подводим итоги»; оригинал: What is Claude Code? / Getting Hands On / Hooks and the SDK / Wrapping Up). В ней рассматривается режим планирования, но не откат и не сжатие контекста как способ управления. Ссылайтесь на версию Skilljar. Anthropic нигде не называет эти четыре глагола «циклом»: это четыре последовательных раздела программы.

<a id="2-context-engineering-is-now-a-layered-system-high-confidence"></a>
### 2. Контекстная инженерия стала многоуровневой системой (высокая уверенность)

Урок уже нигде не сводится к «Напишите CLAUDE.md» ("Write a CLAUDE.md"). Каждая текущая программа учит работать с несколькими уровнями.

Цель Anthropic «Настройте Claude» ("Configure Claude"), перевод:

> Написать компактный CLAUDE.md, которому Claude действительно следует, оформить повторяющиеся процедуры как навыки, выбирать подходящий режим разрешений для каждой задачи и обеспечивать соблюдение обязательных правил с помощью хуков.

Оригинал, дословно:

> write a lean CLAUDE.md Claude actually follows, package repeated
> procedures as skills, pick the right permission mode for each job, and
> enforce the non-negotiable rules with hooks

Уроки: «CLAUDE.md, которому следуют» ("A CLAUDE.md That Follows"), «Навыки проверки» ("Verification Skills"), «Режимы разрешений» ("Permission Modes"), «Хуки» ("Hooks").

GH-300, перевод: «Использовать Spaces, Spark, сводки Pull Request и настраиваемые стандарты ревью через файлы инструкций» и «включать повторное использование файлов промптов для единообразных ответов».

Оригиналы, дословно: "Utilize Spaces, Spark, Pull Request summaries, and customizable review standards via instructions files" и "include prompt file reuse for consistent responses".

Модуль 3 Vanderbilt «Создание процесса и контекста в Claude Code» ("Building Process & Context in Claude Code"): видео «Глобальный постоянный контекст: CLAUDE.md» ("Global Persistent Context: CLAUDE.md"), «Повторно используемые целевые контекст и процесс: команды Claude Code» ("Reusable Targeted Context & Process: Claude Code Commands"), «Обучение в контексте: обучение на примерах» ("In-Context Learning: Teaching with Examples").

<a id="3-agentsmd-is-an-ecosystem-fact-not-a-curriculum-fact-medium-confidence"></a>
### 3. AGENTS.md является фактом экосистемы, но не учебных программ (средняя уверенность)

**Ни одна проверенная программа не преподаёт `AGENTS.md` как стандарт, общий для разных поставщиков.**

- Полное чтение списка проверяемых навыков GH-300 (около 1,076 слов, все 6 областей): строки `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `copilot-instructions.md` не встречаются нигде. Область «промпт-инжиниринг и формирование контекста» ("prompt engineering and context crafting") вообще не называет никаких форматов файлов.
- Поиск grep без учёта регистра по всему пакету Stanford CS146S (204,922 байта, все 10 недель) строк `AGENTS.md` / `CLAUDE.md`: **ноль совпадений**.
- Vanderbilt преподаёт специфичный для поставщика `CLAUDE.md`.
- DeepLearning.AI вместо этого использует файлы «конституции» проекта ("constitution").

При этом *продукты* поддерживают его: GitHub Changelog от 2025-08-28, «Агент Copilot для программирования теперь поддерживает пользовательские инструкции AGENTS.md» ("Copilot coding agent now supports AGENTS.md custom instructions"); GitHub Docs указывает «один файл CLAUDE.md или GEMINI.md, сохранённый в корне репозитория» ("a single CLAUDE.md or GEMINI.md file stored in the root of the repository").

**Интерпретация:** сертификации отстают от продукта. `AGENTS.md` является реальным соглашением экосистемы, которое пока не освоено ни одной рассмотренной программой.

**Оговорка:** это аргумент на основании отсутствия в опубликованных целях; Microsoft предупреждает, что пункты «призваны показать, как мы оцениваем этот навык» ("are intended to illustrate how we are assessing that skill").

**Вывод для нас:** преподавать `AGENTS.md` обоснованно и, вероятно, правильно, но подавать его следует как *переносимое соглашение*, а не как *то, чему учат все*.

<a id="4-spec-driven-development-is-a-standalone-mainstream-unit-high-confidence"></a>
### 4. Разработка по спецификации стала самостоятельной распространённой темой (высокая уверенность)

Это самый большой пробел в сравнении с нашим существующим планом. Обобщаемая схема: постоянная **конституция** проекта плюс **спецификации отдельных функций**, на основе которых работает повторяемый цикл **планировать → реализовывать → валидировать** с обязательным контрольным этапом валидации. Подход прямо позиционируется как дисциплинированная альтернатива вайб-кодингу.

Маршрут из 15+ уроков DeepLearning.AI: зачем SDD → обзор рабочего процесса → создание конституции → спецификация функции → реализация функции → валидация функции → перепланирование проекта → второй этап функциональности → MVP → поддержка унаследованного кода → создание собственного процесса → заменяемость агента → оцениваемый тест.

Оригинальная последовательность: Why SDD → Workflow overview → Creating the constitution → Feature specification → Feature implementation → Feature validation → Project replanning → Second feature phase → MVP → Legacy support → Build your own workflow → Agent replaceability → graded quiz.

Результаты обучения, перевод с сохранением дословных оригиналов:

> Применять повторяемый процесс «планировать, реализовывать, проверять» к новым и унаследованным кодовым базам.

Оригинал:

> Apply a repeatable plan-implement-verify workflow to fresh and legacy
> codebases

> Понимать, почему подробные спецификации позволяют создавать более качественное и удобное в сопровождении ПО, чем вайб-кодинг.

Оригинал:

> Understand why detailed specs produce better, more maintainable
> software than vibe coding

> Сохранять контекст между сессиями агента, повышать точность следования замыслу и сокращать когнитивный долг.

Оригинал:

> preserve context across agent sessions, improve intent fidelity, and
> reduce cognitive debt

Официальный репозиторий подтверждает два уровня в виде готовых артефактов: Video06 «Конституция подготовлена» ("Constitution in place", `specs/mission.md`, `tech-stack.md`, `roadmap.md`), Video07 «Конституция + спецификация функций этапа 1» ("Constitution + Phase 1 feature spec", `plan.md`, `requirements.md`, `validation.md`).

TalTech независимо посвящает теме четыре последовательные лекции: «22 - Разработка по спецификации» ("22 - Spec Driven Development"), "23 - OpenSpec", "24 - Spec Kit", "25 - BMAD".

> [!IMPORTANT]
> Разделение на три файла mission/tech-stack/roadmap **специфично для этого курса**. GitHub Spec Kit использует один `constitution.md`. Учите схеме, а не именам файлов.

<a id="5-verification-has-replaced-diff-reading-high-confidence"></a>
### 5. Проверка пришла на смену чтению diff (высокая уверенность)

Самое заметное качественное изменение по сравнению с подходом «человек просматривает diff». Три отдельные практики, которым можно обучать:

**(a) Самокритика по критериям.** Vanderbilt, перевод: «Научите Claude Code критически оценивать собственный код с помощью контекстных критериев, которые выявляют ошибки ещё до того, как вы их увидите».

Оригинал, дословно: "Teach Claude Code to critique its own code using contextual rubrics that catch bugs before you ever see them."

**(b) Best-of-N.** Vanderbilt, перевод: «Используйте шаблон “Best of N” с Claude Code, чтобы создавать 3-5 вариантов каждой функции и выбирать лучшие части».

Оригинал, дословно: "Use the 'Best of N' pattern with Claude Code to generate 3-5 versions of every feature and cherry-pick the best parts."

Урок: «Шаблон Best of N: используйте преимущество низкой стоимости труда ИИ» ("The Best of N Pattern: Leverage AI Labor Cost Advantages").

**(c) Проверка автономных запусков после их завершения.** Модуль 4 Anthropic «Проверяйте и делитесь» ("Verify and Share") включает урок «Доверяйте результату: проверка запусков без надзора» ("Trust It: Verifying Unsupervised Runs"). Модуль 2 включает «Навыки проверки» ("Verification Skills"): проверка оформляется как повторно используемый *артефакт*, а не разовый просмотр человеком.

DeepLearning.AI делает «Валидацию функции» ("Feature Validation") обязательным именованным шагом каждого цикла разработки функции.

**Оговорка:** «выход за рамки построчного ревью» ("going beyond line-by-line review") является интерпретацией аналитика, а не формулировкой курса.

<a id="6-parallel-agents-are-beginner-level-content-high-confidence"></a>
### 6. Параллельные агенты входят в материал для начинающих (высокая уверенность)

Модуль 4 Vanderbilt «Контроль версий и параллельная разработка с Claude Code» ("Version Control & Parallel Development with Claude Code"): материалы для чтения «Как разрешить Claude Code работать параллельно с Git Worktrees» ("Allowing Claude Code to Work in Parallel with Git Worktrees"), «Субагенты и задачи Claude» ("Claude Subagents & Tasks"), «Параллельная разработка функций с субагентами, задачами и Git Worktrees» ("Parallel Feature Development with Subagents, Tasks, and Git Worktrees"). Описание курса, перевод: учащиеся «координируют Claude Code, работающий одновременно в нескольких ветках git, с параллельными ИИ-агентами, которые одновременно разрабатывают разные функции и автоматически интегрируют свою работу».

Оригинал: "orchestrate Claude Code working concurrently across multiple git branches, with parallel AI agents developing different features simultaneously and automatically integrating their work."

Coursera помечает курс как **Beginner** («для начинающих»).

GH-300, перевод: «управлять сессиями агентов и делегировать задачи субагентам для оптимального использования контекста».

Оригинал, дословно: "manage Agent Sessions and delegate tasks to Sub-Agents for optimized context usage".

> [!NOTE]
> **Оговорка о глубине.** Модуль Vanderbilt занимает около 36 минут в курсе продолжительностью около 5 часов; из этих минут 30 отведены на чтение. Материал GH-300 о субагентах представлен одним пунктом одной подцели. Наличие темы хорошо подтверждено, глубина её изучения нет.

<a id="7-automation-outside-the-interactive-session-is-its-own-module-high-confidence"></a>
### 7. Автоматизация вне интерактивной сессии выделена в отдельный модуль (высокая уверенность)

Модуль 3 Anthropic «Автоматизируйте повторяющуюся работу» ("Automate Repeat Work"), уроки «Регулярные задачи и режим без интерфейса» ("Routines and Headless") и «GitHub Actions и ревью кода» ("GitHub Actions and Code Review"). Основной текст, перевод: «планировать выполнение промптов как регулярных задач на инфраструктуре Anthropic», «переходить в режим без интерфейса, когда задаче нужен собственный конвейер», «подключать Claude к pull request с помощью управляемого ревью кода и GitHub action».

Оригиналы: "schedule prompts as routines on Anthropic infrastructure", "drop to headless mode when a job needs your own pipeline", "wire Claude into pull requests with managed code review and the GitHub action".

Claude Code Routines вышли в исследовательской предварительной версии 2026-04-14.

В GH-300 есть именованный подраздел «Использование GitHub Copilot CLI» ("Use GitHub Copilot CLI") на одном уровне с «Использованием GitHub Copilot в IDE» ("Use GitHub Copilot in the IDE"). Он присутствует с январской редакции 2026 года, то есть является устойчивой частью, а не предварительной версией.

<a id="8-agent-security-has-a-dedicated-week-at-both-universities-high-confidence"></a>
### 8. Безопасности агентов посвящена отдельная неделя в обоих университетах (высокая уверенность)

В нашем плане Модуля 1 эта тема полностью отсутствует.

Неделя 6 Stanford CS146S «Тестирование и безопасность ИИ» ("AI Testing and Security"): темы «Безопасный вайб-кодинг» ("Secure vibe coding"), «История обнаружения уязвимостей» ("History of vulnerability detection"), «Наборы тестов, сгенерированные ИИ» ("AI-generated test suites"). Материалы для чтения включают «Удалённое выполнение кода в Copilot через инъекцию промпта» ("Copilot Remote Code Execution via Prompt Injection", embracethered.com), «Поиск уязвимостей в современных веб-приложениях с Claude Code и OpenAI Codex» ("Finding Vulnerabilities in Modern Web Apps Using Claude Code and OpenAI Codex", semgrep.dev), «Угрозы агентного ИИ» ("Agentic AI Threats", Unit 42), OWASP Top Ten, «Деградация контекста: как ухудшается работа контекстных окон ИИ» ("Context Rot: Understanding Degradation in AI Context Windows", Chroma). Оцениваемое задание: «Найдите и исправьте уязвимости с Semgrep» ("Scan and Fix Vulnerabilities with Semgrep"): запустить Semgrep на приложении FastAPI/JS, разобрать и устранить ≥3 проблемы. Приглашённый спикер: Isaac Evans, CEO Semgrep.

Лекция TalTech «53 - Безопасность и безопасное поведение» ("53 - Security and Safety") охватывает «смертельную троицу» (закрытые данные + содержимое под контролем атакующего + внешние коммуникации), прямые и косвенные инъекции промптов, отравление RAG и памяти, OWASP LLM Top 10, ограничение возможностей, этапы авторизации с участием человека, изоляцию в песочнице и шесть специфичных для MCP классов атак, включая подмену поведения инструмента через другой инструмент (tool shadowing) и «запутавшегося заместителя» (confused deputy).

<a id="9-the-agent-manager-framing-is-explicit-high-confidence"></a>
### 9. Роль «менеджера агентов» сформулирована явно (высокая уверенность)

Неделя 4 Stanford «Шаблоны агентов для программирования» ("Coding Agent Patterns"), ровно две темы: «Управление уровнями автономности агента» ("Managing agent autonomy levels"), «Шаблоны сотрудничества человека и агента» ("Human-agent collaboration patterns"). Лекция в понедельник буквально называется «Как быть менеджером агентов» ("How to be an agent manager"). В пятницу приглашённую лекцию читает Boris Cherny, создатель Claude Code.

Аналогичная рамка у Vanderbilt, перевод: «координировать Claude Code как технический руководитель, управляющий несколькими старшими разработчиками» / «рассматривать ИИ как масштабируемый труд разработчиков».

Оригиналы: "orchestrate Claude Code like a tech lead managing multiple senior developers" / "treating AI as scalable development labor".

### 10. MCP изучается через практическую разработку (высокая уверенность)

Оцениваемое задание Недели 3 Stanford «Создайте собственный MCP-сервер» ("Build a Custom MCP Server"): критерии на 90 баллов, обёртка над реальным внешним API, 2+ инструмента MCP, транспорт STDIO или HTTP, обработка ошибок и ограничений частоты запросов, +5 дополнительных баллов за развёрнутый удалённый HTTP-сервер, +5 за аутентификацию OAuth2/API-key с проверкой аудитории (audience).

*(Относится к нашему Модулю 3, а не Модулю 1.)*

<a id="11-governance-outweighs-prompt-engineering-medium-confidence"></a>
### 11. Управление использованием ИИ весит больше промпт-инжиниринга (средняя уверенность)

Веса областей GH-300 из раздела «Навыки, оцениваемые по состоянию на 7 августа 2026 года» ("Skills measured as of August 7, 2026"); оригинальные названия и точные веса сохранены рядом с переводом:

| Область | Вес |
|---|---|
| Ответственно использовать GitHub Copilot (Use GitHub Copilot responsibly) | 15–20% |
| Использовать возможности GitHub Copilot (Use GitHub Copilot features) | 25–30% |
| Понимать данные и архитектуру GitHub Copilot (Understand GitHub Copilot data and architecture) | 10–15% |
| Применять промпт-инжиниринг и формирование контекста (Apply prompt engineering and context crafting) | 10–15% |
| Повышать продуктивность разработчика с GitHub Copilot (Improve developer productivity with GitHub Copilot) | 10–15% |
| Настраивать конфиденциальность, исключения содержимого и защитные меры (Configure privacy, content exclusions, and safeguards) | 10–15% |

Три уточнения:

1. 15–20% + 10–15% = 25–35%, поэтому говорите «от четверти до трети», а не «треть».
2. В опубликованном списке действительно есть **ошибка дублирования** Microsoft ("Use GitHub Copilot features" и "GitHub Copilot features" оба имеют вес 25–30%), поэтому сумма весов составляет 105–135%. Прежде чем считать доли, удалите дубликат.
3. Называть это «проверкой с участием человека» ("human-in-the-loop verification") было бы преувеличением: только один из пяти пунктов области ответственного использования касается проверки результата; остальные посвящены этике и вреду GenAI, а область конфиденциальности в основном состоит из административных настроек.

Ключевое сравнение сохраняется при любом прочтении: одно только ответственное использование имеет больший вес, чем промпт-инжиниринг.

<a id="12-evals-as-the-spec-for-non-deterministic-systems-medium-confidence"></a>
### 12. Evals как «спецификация для недетерминированных систем» (средняя уверенность)

Лекции TalTech: «51 - Ошибки, детерминизм, наблюдаемость» ("51 - Errors, Determinism, Observability"), «52 - Оценивание и тестирование» ("52 - Evaluation and Testing"), «53 - Безопасность и безопасное поведение» ("53 - Security and Safety"), «54 - Масштабирование агентов: стоимость и многоагентная координация» ("54 - Scaling Agents: Cost and Multi-Agent Coordination").

Лекция 52 рассматривает пять основных метрик (выполнение задачи, точность использования инструментов, стоимость, задержка, стабильность), семь методик оценивания (программные проверки, эталонные наборы данных, LLM в роли судьи), фреймворк Inspect с разобранными примерами, интеграцию с CI, оценивание многоагентных систем. Исходный тезис, перевод:

> Оценивания являются спецификацией для недетерминированных систем. Модульные тесты работают, потому что f(2) == 4 каждый раз. У цикла, управляемого LLM, такой гарантии нет.

Оригинал, дословно:

> Evaluations are the spec for non-deterministic systems. Unit tests work
> because f(2) == 4 every time. An LLM-driven loop has no such guarantee.

**Уверенность средняя, потому что n=1**: один факультативный магистерский курс на эстонском языке, около 60 студентов. Это свидетельство существования практики в заслуживающем доверия учебном заведении, а не отраслевой стандарт.

<a id="13-benchmarks-are-essentially-untaught-medium-confidence"></a>
### 13. Бенчмарки практически не преподаются (средняя уверенность)

Поиск grep по полному пакету Stanford размером 204,922 байта по выражениям `swe.?bench`, `terminal.?bench`, `benchmark`, `eval[su]`, `worktree`, `sub.?agent`, `parallel agent`, `token`, `cost`: **ноль совпадений**. Другие проверенные программы их тоже не называют. TalTech учит создавать собственные локальные наборы оценивания на Inspect, явно выбирая Inspect вместо Braintrust («наборы оценивания, которыми владеете вы», "eval suites you own"), а не публичные таблицы лидеров.

**Вывод:** бенчмарки относятся к *грамотному выбору инструментов* (как читать заявления поставщика), а не к навыку, который нужно практиковать. На эту тему достаточно сегмента максимум на 10 минут.

4. **«Просмотреть diff от ИИ» превращается в проверку.** Критерии оценивания, самокритика, контрольные этапы валидации, Best-of-N и проверка запусков без надзора.
5. **Управление сессией получает конкретные приёмы:** режим планирования, сжатие контекста, откат, работа под надзором или автономно, вместо абстрактной схемы цикла.
6. **Решить, нужно ли введение в безопасность.** Два университета отводят ей целую неделю; у нас есть целый Модуль 4. Варианты: короткое введение в инъекции промптов и ограничение разрешений в Модуле 1 либо полностью отложить тему, прямо сообщив об этом.

<a id="follow-up-loop-engineering-and-graph-engineering"></a>
## Дополнительное исследование: «инженерия циклов» и «инженерия графов»

Два термина, предложенных для модуля, которые вообще не обнаружились в основном исследовании: "loop engineering" и "graph engineering". Изучены отдельно 2026-07-21. **Ни один не является устоявшимся термином.** Они сильно различаются по объёму реальной практики за ними.

<a id="loop-engineering--real-practice-unstable-name-6-7-weeks-old"></a>
### Инженерия циклов (loop engineering): реальная практика, неустоявшееся название (возраст около 6-7 недель)

Появилась в начале июня 2026 года. Хронология первичных источников:

| Дата | Источник | Тип |
|---|---|---|
| Примерно начало июня 2026 | Boris Cherny (руководит Claude Code в Anthropic), публикация в X | Первоначальный импульс |
| 2026-06-07 | [Addy Osmani, «Инженерия циклов» ("Loop Engineering")](https://addyosmani.com/blog/loop-engineering/) | Лучший единичный первичный источник |
| 2026-06-09 | [Эссе Cobus Greyling](https://cobusgreyling.substack.com/p/loop-engineering) + [репозиторий](https://github.com/cobusgreyling/loop-engineering) (8.9k звёзд) | Практик + инструменты |
| 2026-06-23 | [Caspar Bannink, Towards AI](https://pub.towardsai.net/loop-engineering-is-the-new-agentic-engineering-180a59d748bf) | Практик |
| **2026-06-30** | [Anthropic, «Начало работы с циклами» ("Getting started with loops")](https://claude.com/blog/getting-started-with-loops) | **Документация самого поставщика** |
| Июль 2026 | [aipatternbook.com/loop-engineering](https://aipatternbook.com/loop-engineering) | Наиболее ясное техническое определение |
| Июль 2026 | Глоссарий IBM, SEO-фабрики контента | Подхват на стадии модного слова |

**Что это значит.** Проектирование внешней системы управления, которая многократно вызывает агента с течением времени, а не отдельного промпта или запуска. Пять повторяющихся компонентов:

1. **Поиск следующей задачи (Discovery):** как система решает, что делать дальше (падающие тесты, очередь задач, сигнал CI, расписание).
2. **Изолированная передача (Isolated handoff):** упаковка задачи в песочницу (рабочие деревья git, временные ветки).
3. **Независимая проверка (Independent verification):** проверка результата средствами, которые агент не писал (тесты, линтеры, отдельный оценщик, CI).
4. **Сохранение состояния (State persistence):** устойчивое сохранение прогресса между итерациями (`STATE.md`, история PR, трекер задач).
5. **Условие остановки (Stop condition):** цель достигнута, достигнут бюджетный предел, исчерпан лимит итераций, требуется решение человека.

Все источники, которые рассматривают этот вопрос, позиционируют подход как **следующий слой, а не замену**: промпт-инжиниринг → контекстная инженерия → инженерия среды выполнения агента → инженерия циклов.

Оригинальная последовательность: prompt engineering → context engineering → harness engineering → loop engineering.

Контекстная инженерия определяет, что поступает в один вызов; инженерия циклов определяет, как часто, для чего и с какой проверкой агент вообще вызывается.

Anthropic воплотила это в продукте: `/goal`, `/loop`, `/schedule` в Claude Code; выделены четыре типа циклов (по ходам, по цели, по времени, проактивные; оригинал: turn-based, goal-based, time-based, proactive).

**Статус:** не устоялся. Существуют как минимум четыре конкурирующие трактовки. Шесть недель от появления слова до SEO-фабрик контента являются типичным распространением модного термина. Но лежащая в основе практика действительно реализована и используется, поэтому термин обозначает нечто реальное.

**Лучшая формулировка для обучения** (aipatternbook.com), перевод:

> Предел автономности определяется тем, насколько далеко простирается проверка.

Оригинал:

> the autonomy ceiling is set by verification reach

**Оговорка об источниках от исследовавшего агента:** большинство страниц читалось через LLM-суммаризатор, что создаёт риск смысловых сдвигов при пересказе. В частности, цитату Cherny («Я больше не пишу промпты Claude… Моя работа заключается в написании циклов», оригинал: "I don't prompt Claude anymore… My job is to write loops") следует сверить с первоисточником, прежде чем где-либо дословно цитировать её в материалах для учащихся.

<a id="graph-engineering--do-not-build-a-lesson-on-this"></a>
### Инженерия графов (graph engineering): не стройте на этом урок

**Термину три дня.** Он происходит из единственной публикации Peter Steinberger (@steipete) в X от **2026-07-18**: *«Мы всё ещё говорим о циклах или уже перешли к графам?»* Оригинал: *"Are we still talking loops or did we shift to graphs yet?"* (575K просмотров). Сама публикация продолжает его июньский пост об "loop engineering". Ни документация поставщиков, ни учебные программы, ни доклады не используют его как устойчивое понятие: есть лишь SEO-блоги, написанные за 72 часа ([explainx.ai](https://www.explainx.ai/blog/graph-engineering-ai-agents-multi-agent-organizations-2026), [aibuilderclub.com](https://www.aibuilderclub.com/blog/graph-engineering-guide-2026), оба сайта продвигают курсы).

С самим термином спорят люди, которые его используют:

- **Harrison Chase (создатель LangGraph)**, перевод: «Так что я толком не знал, что такое инженерия графов, и до сих пор толком не знаю… но по сути это просто langgraph?» Оригинал: "so i didn't really know what graph engineering is, and i still don't really… but it's basically just langgraph?"
- **Karan Singh**, перевод: «Субагенты с определённой целью и есть граф. Но давайте запутаем всех и назовём это чем-то совершенно новым». Оригинал: "Sub-agents with a defined purpose is a Graph. But yeah lets confuse everyone and call it a net new thing."
- **David K (создатель XState)**, перевод: «Сначала были циклы. Теперь графы. В следующем месяце будет что-то ещё... мы постоянно заново открываем шаблоны разработки ПО, которым уже десятки лет». Оригинал: "First it was loops. Now it's graphs. Next month it'll be something else... we're constantly rediscovering decades-old software engineering patterns."

**Преобладающая трактовка:** оркестрация нескольких агентов как DAG в стиле LangGraph: узлы являются специализированными агентами, рёбра задают маршрутизацию. Трактовка «кодовая база как граф» (графы вызовов, графы зависимостей, карты репозитория) **вообще не обнаружилась** под этим названием, хотя это реальная практика с реальными инструментами (repo-map Aider, Sourcegraph, CodeQL, Joern).

> [!WARNING]
> **Совпадение названий.** У "Graph engineering" уже есть устоявшееся, не связанное с этим значение в инженерии данных и сетевом анализе: графовые базы данных, схемы, Cypher, масштабные графовые алгоритмы. Это старое значение устойчиво и реально. Значение в сфере программирования с ИИ является совершенно новым разговорным выражением, повторно использующим те же два слова. Курс DeepLearning.AI по графам знаний от Andreas Kollegger из Neo4j оказался втянут в ту же дискуссию в X только из-за совпадения по времени: в нём этот термин не используется.

**Рекомендация:** не называйте этим термином урок. Курс записывается сейчас и начинается 2026-08-31; урок, названный в честь твита трёхдневной давности, быстро устареет за считаные недели. Вместо этого преподавайте долговечную суть: параллельные агенты на рабочих деревьях и субагенты, которые основное исследование независимо подтвердило как *распространённый материал для начинающих* (модуль Vanderbilt, цель GH-300). Модное слово заслуживает одной честной ремарки как пример того, насколько быстро меняется эта лексика.
