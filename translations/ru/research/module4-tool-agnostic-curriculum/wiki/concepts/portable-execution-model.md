# Переносимая модель выполнения

> Исследовательский архив. Перевод исторических рабочих материалов; утверждения о продуктах, моделях, командах и доступности отражают исходный документ и могут быть устаревшими. Упоминания согласования и проверок относятся к работе авторов оригинала, а не к новому согласованию или проверке при переводе.

<a id="baseline-contract"></a>
## Базовый контракт

- [HUMAN] Реализация должна работать с Codex, Claude Code и сопоставимыми терминальными агентами в интерактивном или неинтерактивном режиме.
- [INFERENCE current-module-4,tool-repositories] Минимальный общий интерфейс должен состоять из файлов репозитория и обычных CLI-программ, а не из плагина, хука или конфигурации MCP, специфичных для поставщика.
- [INFERENCE nist-ssdf,opentelemetry-signals] Производителям свидетельств следует отдавать предпочтение детерминированным командам, явным входам, версионируемой конфигурации, коду завершения и структурированному выводу, где он доступен.
- [INFERENCE owasp-prompt-injection,mcp-security] Рассуждающий агент должен получать только необходимые свидетельства, работать с явной областью доступа к файловой системе/сети/секретам и требовать одобрения перед существенными изменениями состояния.
- [INFERENCE nist-ai-rmf] Для неинтерактивных запусков нужны объявленная задача, разрешённые действия, политика данных, схема вывода, граница времени/стоимости и сохраняемая запись аудита.

<a id="separation-of-responsibilities"></a>
## Разделение ответственности

Сборщик/проверяющий компонент → файлы свидетельств → кодинг-агент → предлагаемое решение/действие → политика и барьер одобрения → команда действия → независимая проверка.

Исходная схема:

```text
collector/checker -> evidence files -> coding agent -> proposed decision/action
                                            |
                                  policy + approval gate
                                            |
                                      action command
                                            |
                                    independent verify
```

Агент может вызывать каждый этап, но этапы должны оставаться отдельно наблюдаемыми. Это не даёт убедительному рассказу скрыть недостающие свидетельства или непроверенное действие.

<a id="feasible-do-it-yourself-building-blocks"></a>
## Реализуемые самостоятельно строительные блоки

- [INFERENCE current-module-4] Модель рисков и перечень возможностей в Markdown/JSON.
- [INFERENCE nist-ssdf,owasp-secure-code-review] Shell-скрипт или скрипт исполнителя задач, который запускает существующие линтеры, тесты, проверки зависимостей и политик и нормализует результаты.
- [INFERENCE owasp-secure-code-review] Переносимый файл промпта/задачи для проверки, принимающий diff, спецификацию, заметки об угрозах и вывод проверок.
- [INFERENCE opentelemetry-signals,nist-incident-response] Подготовленный пакет эксплуатационных свидетельств и шаблон расследования.
- [INFERENCE nist-ai-rmf] Небольшой файл политики и обёртка, разрешающая или запрещающая сочетания модели, данных и действия.
- [INFERENCE nist-ai-rmf,mcp-security] События аудита JSON Lines, фиксирующие участника, задачу, входные данные по ссылке, команду инструмента, результат, одобрение и проверку.

[INFERENCE nist-ssdf,current-module-4] «Реализовать самим» должно означать сборку слоя управления и рабочего процесса свидетельств, а не повторную реализацию статического анализа, обнаружения секретов, сбора телеметрии или обслуживания моделей.
