# Пересмотренная архитектура модуля

> Исследовательский архив. Перевод исторических рабочих материалов; утверждения о продуктах, моделях, командах и доступности отражают исходный документ и могут быть устаревшими. Упоминания согласования и проверок относятся к работе авторов оригинала, а не к новому согласованию или проверке при переводе.

<a id="system-path"></a>
## Путь через систему

React, FastAPI и Postgres из Модуля 2 → инструментация OpenTelemetry → OpenTelemetry Collector → метрики в Prometheus, логи в Loki и трассировки в Tempo → дашборды и алерты Grafana → оркестратор инцидента → изолированный кодинг-агент первой линии. Далее либо известная безопасная процедура и проверка восстановления, либо эскалация человеку с пакетом свидетельств.

Исходная схема:

```text
React + FastAPI + Postgres from Module 2
                 |
       OpenTelemetry instrumentation
                 |
        OpenTelemetry Collector
          /          |          \
 Prometheus       Loki         Tempo
   metrics        logs         traces
          \          |          /
                  Grafana
             dashboards + alerts
                       |
              incident orchestrator
                       |
          sandboxed first-line coding agent
             /                       \
 known safe runbook             human escalation
       |                        + evidence packet
 verify recovery
```

- [HUMAN] Предметом являются приложение и конвейер развёртывания из Модуля 2.
- [INFERENCE observability-pipeline] Приложение отправляет стандартную телеметрию в одну конечную точку коллектора; хранилище и визуализация остаются заменяемыми.
- [INFERENCE alerting-sre] Дашборды показывают трафик, ошибки, задержки, насыщение, работоспособность и контекст недавних развёртываний; алерты сосредоточены на устойчивых симптомах, видимых пользователю.
- [INFERENCE safe-remediation] Агент начинает только с чтения, собирает свидетельства и может перейти к изменению состояния лишь через допустимую предварительно согласованную процедуру.
- [INFERENCE safe-remediation,nist-incident-response] Каждое реагирование завершается проверкой восстановления или готовой для человека эскалацией и создаёт запись аудита.

<a id="recommended-teaching-stack"></a>
## Рекомендуемый учебный стек

- [INFERENCE observability-pipeline,alerting-sre] **Ядро:** OpenTelemetry SDK/автоинструментация, исходный OpenTelemetry Collector, Prometheus, Loki, Tempo, Grafana, совместимый с Alertmanager webhook, один терминальный кодинг-агент.
- [FACT observability-pipeline,alerting-sre] **Почему Loki и Tempo:** метрики могут сообщить учащимся, что система нездорова; связанные логи и трассировки помогают объяснить, какой запрос и компонент дали сбой.
- [INFERENCE observability-pipeline] **Почему исходный Collector:** он учит стандартной границе и не привязывает инструментацию к специфичному для Grafana синтаксису сбора. Grafana Alloy можно рассмотреть в сравнении для продакшена.
- [FACT observability-pipeline] **Выбор области:** в основной лабораторной работе инструментировать бэкенд FastAPI для трассировок и метрик и связывать структурированные stdout-логи. Браузерная трассировка необязательна, поскольку текущая браузерная инструментация OpenTelemetry экспериментальна.

<a id="minimal-alerts"></a>
## Минимальные алерты

1. Публичная проверка работоспособности/доступности не проходит в течение устойчивого интервала.
2. Повышена доля видимых пользователю ошибок/5xx.
3. Повышена задержка запросов p95.
4. Необязательно: насыщение, например нехватка соединений БД или ресурсов хоста/контейнера.
5. Метамониторинг: перестал работать сам путь телеметрии/алертов. [INFERENCE alerting-sre]

Эти алерты следует намеренно вызывать подготовленными сценариями отказа, а не оставлять декоративным YAML.
