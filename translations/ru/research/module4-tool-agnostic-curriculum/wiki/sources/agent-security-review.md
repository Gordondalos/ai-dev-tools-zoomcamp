# Официальные рекомендации по проверке безопасности с помощью агентов

Основные источники:

- [FACT agent-security-review] https://support.anthropic.com/en/articles/11932705-automated-security-reviews-in-claude-code/
- [FACT agent-security-review] https://developers.openai.com/codex/use-cases
- [FACT agent-security-review] https://red.anthropic.com/2026/cvd/

Кратко: современные продукты с агентами для программирования поддерживают проверку по запросу, по событию изменения и глубокую проверку репозитория, однако их разработчики всё равно сохраняют детерминированные проверки и валидацию человеком.

- [FACT agent-security-review] Документация Claude Code описывает проверку безопасности по запросу в терминале и автоматическую проверку pull request, подчёркивая, что они дополняют, а не заменяют существующие практики безопасности и ручную проверку.
- [FACT agent-security-review] Официальные сценарии использования Codex включают сканирование безопасности с акцентом на изменения, глубокое сканирование репозитория, аудит при инцидентах с зависимостями и устранение проблем с подтверждением отсутствия регрессий.
- [FACT agent-security-review] Программа раскрытия уязвимостей Anthropic 2026 года использует внешнюю первичную оценку и проверку людьми перед сообщением о находках высокой/критической серьёзности; проверка человеком описывается как этап, ограничивающий скорость процесса.
- [INFERENCE agent-security-review,owasp-secure-code-review] Находку модели следует принимать только тогда, когда она указывает на конкретные свидетельства в коде/конфигурации, правдоподобный путь к последствиям и воспроизводимый метод проверки; согласие двух моделей помогает расставлять приоритеты, но не служит доказательством.

Ограничения: документация продуктов отчасти рекламная и не устанавливает сравнительную точность обнаружения. Курс должен оценивать процесс на известных тестовых примерах, а не заявлять, что одна модель является лучшим аудитором.
