# Живой воркшоп по статье 3

Расположение: `https://www.youtube.com/watch?v=gxt5ZDVnBMM`

Воркшоп от 10 августа применяет последовательность черновика статьи 3 к приложению interview-canvas и предоставляет реальные промпты, проверки, облачные решения и ошибки для правок после воркшопа.

- [FACT article-3-live-workshop] Разбор начинается с `npm run dev` для фронтенда и `make run` для бэкенда, затем собирается один многоэтапный образ и добавляется именованный том SQLite, чтобы данные переживали перезапуски контейнера.
- [FACT article-3-live-workshop] При проверке Postgres задаётся `SDIP_DATABASE_URL`, перезапускается бэкенд и подтверждается сохранность данных.
- [FACT article-3-live-workshop] Compose добавляет проверку работоспособности Postgres и ожидает готовности базы данных перед запуском приложения. Приложение переносится на порт хоста 8100, поскольку порт 8000 уже занят.
- [FACT article-3-live-workshop] Playwright автоматизирует тот же сценарий в двух браузерах, который использовался при ручных проверках: вход интервьюера, создание сессии, присоединение кандидата, редактирование холста кандидатом и проверка со стороны интервьюера.
- [FACT article-3-live-workshop] Для AWS выбраны EC2 и Docker Compose, а CloudFormation обязателен, чтобы все ресурсы можно было проверить и удалить вместе.
- [FACT article-3-live-workshop] В показанном прототипе Postgres остаётся на томе EC2. Автор рекомендует управляемый RDS и резервные копии для приложения, данные которого важны.
- [FACT article-3-live-workshop] Автор проверяет сгенерированные ресурсы, запрашивает оценку стоимости, позже сверяет реальный счёт и наблюдает за агентом, пока у того есть временный административный доступ.
- [FACT article-3-live-workshop] GitHub Actions сначала запускает задания бэкенда и фронтенда, затем интеграционные и сквозные тесты и наконец развёртывание. OIDC заменяет долгоживущие ключи AWS ролью с ограниченными правами.
- [FACT article-3-live-workshop] Имя стека при удалении ресурсов: `sdip`, а не `interview-canvas`.

Ограничения: в субтитрах YouTube есть ошибки распознавания, поэтому точные команды и исправления после сессии сверены с окончательной версией репозитория и логами GitHub Actions. Запись заканчивается, когда workflow развёртывания ещё исправляется; репозиторий содержит готовое исправление.
