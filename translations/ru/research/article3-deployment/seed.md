# Статья 3: развёртывание приложения Interview Canvas

<a id="intended-reader"></a>
## Целевой читатель

Читатели серии статей AI Dev Tools Zoomcamp, которые прошли статью 2 и теперь имеют локально работающее приложение interview-canvas.

<a id="desired-change"></a>
## Желаемый результат

Показать читателю, как перевести именно приложение из статьи 2 с локальной конфигурации FastAPI/React/SQLite на контейнеризованное, протестированное и развёрнутое приложение с автоматизированным процессом CI/CD.

<a id="core-claim"></a>
## Главная мысль

Развёртывание должно продолжать пошаговый процесс работы с ИИ из статьи 2: попросить одно ограниченное изменение, запустить результат, диагностировать сбои на основе свидетельств и лишь затем переходить к следующему слою.

<a id="brain-dump"></a>
## Исходные мысли

Сейчас статья 3 представляет собой незавершённый фрагмент, который начинается с интеграционных тестов и контейнеров. Остальной материал находится в полном дневном воркшопе AI Shipping Labs, на который ссылается статья 2. Воркшоп использует Snake Royale, но эта статья должна адаптировать каждый относящийся к делу пример к приложению для интервью по проектированию систем из статьи 2. Вероятная последовательность: введение и повторение; интеграционные тесты; один Docker-образ для фронтенда и бэкенда; Postgres; Docker Compose; облачное развёртывание; GitHub Actions CI/CD; удаление ресурсов и заключение.

<a id="must-use"></a>
## Обязательно использовать

- `articles/02-end-to-end.md` как источник сквозного примера, авторского голоса и точки перехода.
- `articles/03-deployment.md` как существующий фрагмент, который нужно завершить.
- Full-stack-воркшоп от 23 июня в `../ai-shipping-labs-workshops-raw` как источник последовательности развёртывания, промптов, наблюдаемых сбоев и эксплуатационных деталей.
- Текущий репозиторий `interview-canvas-share` как источник реальных имён и структуры проекта.

<a id="must-avoid"></a>
## Обязательно избегать

- Не возвращаться к примеру Snake Royale из воркшопа.
- Не придумывать команды, имена переменных окружения, пути или облачные файлы, которые не поддерживаются репозиторием interview-canvas, без пометки, что это промпты или предлагаемые результаты.
- Не превращать статью в общий каталог платформ развёртывания.
- Не копировать текст воркшопа механически; адаптировать его в одну цельную статью.

<a id="constraints"></a>
## Ограничения

Статья в Markdown по пути `articles/03-deployment.md`. Следовать прямому, практичному, обучающему голосу от первого лица и структуре с промптами из статьи 2. Сохранить достаточно технических подробностей, чтобы читатели могли повторить процесс, но за исчерпывающим разбором направлять к воркшопу. Сохранять формулировки пользователя там, где они полезны, и исправлять очевидные опечатки в новом тексте. Дополнительное веб-исследование за пределами указанного репозитория не требуется, если только технический пробел нельзя устранить локально.
