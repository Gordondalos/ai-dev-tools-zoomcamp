# Agent Relay (стартовый вариант с SQLite)

Agent Relay — небольшой сервис FastAPI для регистрации агентов, выдачи по одной
задаче за раз и сохранения результатов. Локальный стартовый вариант самодостаточен:
SQLite хранит очередь и попытки выполнения, а воркеры выполняют задачи на своих
компьютерах. Включённый воркер детерминированно возвращает `input.upper()`.

<a id="run-it"></a>
## Запуск

```bash
uv sync
uv run uvicorn main:app --reload
```

Откройте <http://127.0.0.1:8000/>, чтобы пользоваться локальной панелью управления с
доступом по токену. База данных по умолчанию — `./agent-relay.db`; задайте
`RELAY_DATABASE_URL`, чтобы использовать другой файл SQLite. `GET /health`
проверяет, что сервис работает, а `GET /ready` — соединение с базой данных.

Зарегистрируйте две идентичности и отправьте задачу:

```bash
alice=$(curl -sS -X POST http://127.0.0.1:8000/api/v1/agents \
  -H 'content-type: application/json' -d '{"name":"alice"}')
bob=$(curl -sS -X POST http://127.0.0.1:8000/api/v1/agents \
  -H 'content-type: application/json' -d '{"name":"uppercase"}')
```

Ответ содержит секретный `token` каждого агента только один раз. Храните его вне
системы контроля версий. Для всех последующих вызовов API используйте
`Authorization: Bearer <token>`; регистрация — единственный эндпоинт без
аутентификации. Для совместной установки задайте `RELAY_ENROLLMENT_SECRET`
и передавайте его как `X-Enrollment-Secret` при регистрации.

<a id="run-the-deterministic-worker"></a>
## Запуск детерминированного воркера

Воркер может зарегистрироваться самостоятельно и сохранить учётные данные
в JSON-файле с правами доступа 0600:

```bash
uv run python main.py worker \
  --base-url http://127.0.0.1:8000 \
  --name uppercase \
  --credentials ./uppercase-credentials.json \
  --worker-id laptop-1
```

Для демонстрации сбоя и повторной доставки намеренно замедлите локальное выполнение
и остановите процесс после одного завершения:

```bash
uv run python main.py worker --credentials ./uppercase-credentials.json \
  --slow-seconds 75 --worker-id slow-laptop
```

Во время долгой работы воркер отправляет heartbeat. Если завершить его процесс,
задача останется закреплённой за ним на срок аренды. После истечения 60-секундной
аренды другой воркер сможет взять задачу с новым токеном и увеличенным номером
попытки. `RELAY_LEASE_SECONDS` и `RELAY_MAX_ATTEMPTS` — настраиваемые параметры сервера.

Существующие учётные данные также можно передать явно (токен не записывается на диск):

```bash
uv run python main.py worker --agent-id agent_123 --token agt_… --worker-id laptop-2
```

<a id="storage-and-delivery-behavior"></a>
## Хранение и поведение доставки

`database.py` содержит модели SQLAlchemy, настройку SQLite WAL и отдельный
вспомогательный механизм транзакций `BEGIN IMMEDIATE`. В `storage.py` находятся
операции с задачами, получением задач и восстановлением; маршруты и модели запросов
хранятся в `main.py` и `schemas.py`. В SQLite нет аналога PostgreSQL
`FOR UPDATE SKIP LOCKED`, поэтому стартовый вариант последовательно выполняет
транзакции записи, делая конкурентное получение задач безопасным между процессами.
Позже студенты могут перенести этот слой хранения на PostgreSQL, не меняя
HTTP-протокол или жизненный цикл из `SPEC.md`.

Задачи выдаются с гарантией «как минимум один раз», а срок аренды по умолчанию
составляет 60 секунд. Heartbeat продлевает действующую аренду. Запрос завершения
или ошибки должен содержать bearer-токен получателя и токен получения задачи
(claim token). Точное повторение завершающего запроса с тем же claim token
идемпотентно; устаревший токен или другой результат получают ответ `409`.

<a id="verify"></a>
## Проверка

Набор тестов покрывает основной протокол, границы доступа отправителя и получателя,
поведение хешированного claim token, идемпотентные повторы завершающих запросов,
конкурентное получение задач, истечение аренды до и после восстановления,
пагинацию и формат ошибок, а также раздачу ресурсов панели управления:

```bash
uv run pytest -q
```

В стартовый вариант намеренно не включены Docker, Kubernetes, CI, внешние брокеры,
LLM и реализация PostgreSQL. Это задачи развёртывания и дальнейшего портирования
студентами, а не часть локального протокола relay.
