# Домашнее задание 2: Создайте и выпустите full-stack-приложение с помощью ИИ

[Оригинал](https://github.com/Gordondalos/ai-dev-tools-zoomcamp/blob/b47dff65161c878d095e288e9f9e5b907f5aa3c6/cohorts/2026/homework/02-development/homework.md)

В этом домашнем задании мы создадим с помощью ИИ полноценное приложение: фронтенд, бэкенд и базу данных.

Для бэкенда понадобятся Python и `uv`, а для фронтенда — Node.js. Знать эти технологии для выполнения задания не обязательно.

Если какие-то вопросы непонятны или вы не уверены, какой ответ выбрать, попросите помощи у своего ИИ-ассистента.

<a id="question-1-pick-your-project"></a>

## Вопрос 1: Выберите проект

Можно выбрать одну из четырёх идей проекта:

- Приложение для разделения общих расходов
- Менеджер списка ожидания в ресторане
- Небольшая канбан-доска
- Табло результатов спортивной лиги

Выберите то, что вам больше нравится. Рабочий процесс одинаков для всех вариантов.

Какой проект вы выбрали для этого домашнего задания?

<a id="question-2-spec-first"></a>

## Вопрос 2: Сначала спецификация

Как и в первом домашнем задании, начнём со спецификации.

Откройте чат с ассистентом и попросите помочь составить спецификацию.

Ответьте на его вопросы, а затем попросите сохранить всё в файл Markdown.

Также попросите помочь придумать название приложения.
Какое название вы выбрали?

<a id="question-3-github-repository"></a>

## Вопрос 3: Репозиторий GitHub

Создайте новый репозиторий GitHub (или папку в репозитории из домашнего задания 1) и клонируйте его локально. Добавьте туда спецификацию:

- `_docs/specs.md` со спецификацией
- `.gitignore`
- `README.md`
- `AGENTS.md`

Создайте коммит и отправьте его в удалённый репозиторий. Каков хеш SHA-1 этого коммита?

<a id="question-4-frontend-prototype"></a>

## Вопрос 4: Прототип фронтенда

Создайте прототип фронтенда с имитацией бэкенда. Для простоты используйте своего агента для программирования напрямую, а не Lovable (хотя с ним тоже можно поэкспериментировать).

```text
Implement the frontend for the app described in _docs/specs.md. Put it in frontent/.

Don't implement the backend yet. Centralize all the backend calls
in one place and mock them for now.

Make the UI interactive so I can use the main features from the spec.
```

Перевод примера:

> Реализуй фронтенд приложения, описанного в `_docs/specs.md`. Помести его в `frontent/`.
>
> Пока не реализуй бэкенд. Собери все обращения к бэкенду в одном месте и пока замени их имитациями.
>
> Сделай интерфейс интерактивным, чтобы я мог пользоваться основными функциями из спецификации.

*Примечание к переводу: написание каталога `frontent/` сохранено из примера в оригинале; вероятно, это опечатка в слове `frontend/`. Выберите единое имя каталога для своего проекта.*

Дорабатывайте решение, пока результат вас не устроит.

Какую команду вы используете для запуска фронтенда?

<a id="question-5-backend"></a>

## Вопрос 5: Бэкенд

Теперь создадим бэкенд. Можно сначала попросить ассистента для программирования проанализировать код фронтенда и составить спецификации, а затем на их основе создать бэкенд. Или можно сразу перейти к его созданию.

Как и на занятиях, сначала создадим бэкенд с имитацией базы данных, убедимся, что он хорошо взаимодействует с фронтендом, а затем заменим имитацию настоящей базой данных.

Запрос может выглядеть так:

```text
Based on openapi.yaml, create a FastAPI backend. Use uv for package management.
Use a mock database, we will replace it with a real one later.
Write tests for the endpoints first, then implement them.
```

Перевод примера:

> На основе `openapi.yaml` создай бэкенд на FastAPI. Используй `uv` для управления пакетами.
> Используй имитацию базы данных: позже мы заменим её настоящей.
> Сначала напиши тесты для эндпоинтов, затем реализуй их.

Какую команду вы используете для запуска бэкенда?

<a id="question-6-connect-frontend-and-backend"></a>

## Вопрос 6: Соедините фронтенд и бэкенд

Теперь бэкенд, предположительно, работает, так что подключим к нему фронтенд. Попросите ассистента для программирования сделать это.

Можно проверить соединение вручную, а можно попросить агента проверить его через браузер.

Какой URL использует фронтенд для обращения к бэкенду?

<a id="question-7-database"></a>

## Вопрос 7: База данных

Теперь, когда бэкенд и фронтенд работают правильно, можно заменить имитацию хранилища настоящей базой данных.

Сохраните независимость приложения от конкретной базы данных, используя SQLAlchemy.

Убедитесь, что тесты по-прежнему проходят, и при необходимости добавьте новые. Попросите агента дать рекомендации.
