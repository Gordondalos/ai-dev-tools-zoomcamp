# Домашнее задание 3: Контейнеризация и развёртывание

[Оригинал](https://github.com/Gordondalos/ai-dev-tools-zoomcamp/blob/b47dff65161c878d095e288e9f9e5b907f5aa3c6/cohorts/2026/homework/03-deployment/homework.md)

В этом домашнем задании вы развернёте Agent Relay — небольшую систему обмена сообщениями между программными агентами.

Один агент отправляет задачу другому, исполнитель забирает её в работу, а затем подтверждает результат. База данных хранит сообщения и попытки их доставки. Небольшая панель мониторинга позволяет следить за жизненным циклом сообщений.

С помощью своего агента для программирования вы протестируете и контейнеризируете Agent Relay. Затем развернёте его в локальном кластере Kubernetes с помощью [kind](https://kind.sigs.k8s.io/) (Kubernetes in Docker).

В стартовом проекте уже есть API и панель мониторинга.

Вам не понадобятся облачный аккаунт, ключ API LLM или внешний брокер сообщений. Всё работает на вашем компьютере. По мере необходимости просите агента устанавливать и проверять каждый инструмент.

<a id="question-1-understand-the-project"></a>

## Вопрос 1: Разберитесь в проекте

Создайте форк стартового репозитория Agent Relay по [этой ссылке](https://github.com/alexeygrigorev/agent-relay).

Попросите агента запустить проект. Попробуйте разобраться в нём и поэкспериментировать.

Какое описание соответствует архитектуре проекта?

- Агенты обмениваются задачами напрямую друг с другом.
- Агенты забирают задачи из базы данных через HTTP API.
- Агенты получают задачи из брокера сообщений.
- Браузер хранит и выполняет задачи.

<a id="question-2-register-agents-and-test-the-task-flow"></a>

## Вопрос 2: Зарегистрируйте агентов и проверьте прохождение задачи

Попросите своего агента для программирования прочитать `SPEC.md` (в корне стартового репозитория) и выполнить первый приёмочный сценарий на локальном Agent Relay:

Зарегистрируйте двух агентов и организуйте обмен задачей и её результатом между ними.

Проверьте результат в панели мониторинга. Затем попросите агента для программирования превратить этот сценарий в интеграционный тест API, работающий с настоящими API и базой данных. Запустите тест и убедитесь, что он проходит.

Какой статус задачи видит отправитель после того, как получатель отправляет результат?

- `queued`
- `processing`
- `completed`
- `delivered`

<a id="question-3-containerization"></a>

## Вопрос 3: Контейнеризация

Попросите агента для программирования создать Dockerfile для Agent Relay. Соберите образ с именем `agent-relay:local` и запустите его, опубликовав порт API на своём компьютере.

Совет: внутри контейнера запускайте uvicorn с `--host 0.0.0.0`, иначе может показаться, что `-p` не работает (по умолчанию uvicorn использует `127.0.0.1`).

Откройте панель мониторинга и повторите сценарий из вопроса 2 с API, работающим в контейнере.

Какой параметр Docker публикует порт контейнера на вашем компьютере?

- `--expose`
- `-p`
- `-v`
- `--name`

<a id="question-4-docker-compose-and-postgresql"></a>

## Вопрос 4: Docker Compose и PostgreSQL

Попросите агента для программирования заменить SQLite на PostgreSQL и создать `compose.yaml`, который запускает Agent Relay и PostgreSQL вместе. Назовите сервис базы данных `postgres`.

Запустите стек:

```bash
docker compose up --build
```

Запустите интеграционный тест из вопроса 2 для стека Compose и проверьте результат в панели мониторинга. Убедитесь, что приложение хранит данные в PostgreSQL.

Какое имя хоста должно использовать API для подключения к сервису `postgres` в Docker Compose?

- `localhost`
- `postgres`
- `host.docker.internal`
- `0.0.0.0`

## Вопрос 5: Развёртывание в Kubernetes

Попросите агента для программирования при необходимости установить [kind](https://kind.sigs.k8s.io/) и kubectl, а затем создать локальный кластер Kubernetes.

Создайте в `k8s/` манифесты для Agent Relay и PostgreSQL, включая ресурсы Service, постоянное хранилище базы данных и проверки готовности. Загрузите Docker-образ в kind и разверните приложение.

Убедитесь, что поды готовы. Откройте панель мониторинга через перенаправление порта и проверьте сценарий из вопроса 2.

Какой ресурс Kubernetes поддерживает заданное число работающих реплик приложения и управляет обновлениями?

- Service

<a id="question-6-cicd"></a>

## Вопрос 6: CI/CD

Попросите агента для программирования создать `.github/workflows/ci.yml`, который запускает тесты стартового проекта и ваш интеграционный тест с PostgreSQL, собирает новый Docker-образ и развёртывает его в кластере kind только при успешном прохождении тестов.

Запустите рабочий процесс локально с помощью [act](https://nektosact.com/). Попросите агента настроить доступ к Docker и кластеру kind, включая загрузку нового образа в kind. Используйте уникальный тег образа для каждой версии и дождитесь завершения развёртывания.

Измените заголовок панели мониторинга на `Agent Relay v2` и запустите рабочий процесс ещё раз. Убедитесь, что тесты проходят, а в развёрнутой панели появился новый заголовок.

Что должно произойти, если один из тестов в этом рабочем процессе завершится ошибкой?

- Развернуть новую версию и сообщить об ошибке.
- Оставить существующую версию работающей и остановить развёртывание.
- Удалить существующее развёртывание.
- Развернуть предыдущий образ с новым тегом.
