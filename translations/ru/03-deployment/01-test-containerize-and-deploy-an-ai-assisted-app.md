# Тестирование, контейнеризация и развёртывание приложения, созданного с помощью ИИ

[Оригинал материала](https://github.com/Gordondalos/ai-dev-tools-zoomcamp/blob/b47dff65161c878d095e288e9f9e5b907f5aa3c6/03-deployment/01-test-containerize-and-deploy-an-ai-assisted-app.md)

<a id="overview"></a>

## Обзор

Модуль 2 заканчивается приложением, которое работает на вашем компьютере. В этом модуле вы пройдёте оставшийся путь: проверите приложение тестами, задействующими реальный стек, упакуете его в контейнеры, настроите автоматические проверки каждого pull request и развернёте его для других пользователей.

Последовательность этапов:

```text
integration tests
containerization
continuous integration
deployment
continuous delivery
```

Перевод схемы:

> интеграционные тесты → контейнеризация → непрерывная интеграция → развёртывание → непрерывная доставка

На каждом этапе ИИ-инструменты хорошо готовят черновой вариант, но плохо справляются с ответственностью за результат. Сгенерированный `Dockerfile`, с которым сборка завершается успешно, не обязательно собирает то, что нужно. А зелёный пайплайн, который пропускает тесты, хуже, чем отсутствие пайплайна. Рабочий процесс остаётся таким же, как в предыдущих модулях: дайте агенту создать первую версию, затем прочитайте её, запустите и намеренно внесите поломку, чтобы проверить, обнаружат ли проверки хоть какую-нибудь проблему.

Продолжайте работать с приложением, созданным в модуле 2.

Краткое содержание модуля: сопроводительная статья показывает переход от локального приложения к общедоступному развёртыванию. В ней добавляются интеграционные и сквозные тесты, фронтенд и бэкенд упаковываются в контейнер, SQLite заменяется на Postgres с помощью Docker Compose, приложение развёртывается в AWS, а доставка автоматизируется через GitHub Actions.

[Читать статью: «Развёртывание full-stack-приложения с ИИ-помощниками для программирования»](https://aishippingblog.com/p/deploy-a-full-stack-app-with-ai-coding)

Вы научитесь:

- Писать интеграционные тесты, которые обращаются к реальной базе данных, покрывают миграции, аутентификацию и взаимодействие фронтенда с бэкендом и выполняются достаточно быстро, чтобы запускаться при каждом push
- Контейнеризировать приложение с помощью многоэтапного Dockerfile и Docker Compose, заменяя SQLite на Postgres
- Настраивать CI в GitHub Actions для запуска линтеров, модульных и интеграционных тестов, а также сборки контейнера для каждого pull request
- Развёртывать приложение по общедоступному URL на платформе вроде Render, Fly.io, Railway или Cloud Run, используя управляемую базу данных и запуск миграций при развёртывании
- Настраивать CI/CD так, чтобы слияние в main было возможно только после успешных тестов и автоматически запускало сборку, миграции и повторное развёртывание
- Добавлять отдельные staging- и production-окружения, smoke-тест после развёртывания и документированный порядок отката

## Результаты работы по модулю

К концу модуля 3 в вашем репозитории должны быть:

```text
tests/integration/
Dockerfile
docker-compose.yml
.github/workflows/ci.yml
.github/workflows/deploy.yml
docs/testing.md
docs/deployment.md
docs/release-process.md
```

Приложение должно быть доступно по общедоступному URL, автоматически пересобираться и развёртываться при слиянии в основную ветку, а также воспроизводиться локально по инструкции из README.
