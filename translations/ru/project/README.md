# Итоговый проект

[Оригинал этой страницы](https://github.com/Gordondalos/ai-dev-tools-zoomcamp/blob/b47dff65161c878d095e288e9f9e5b907f5aa3c6/project/README.md).

В итоговом проекте вы примените полный рабочий процесс курса к одному приложению на свой выбор.

Вы:

- Придумаете идею проекта.
- Определите проблему и критерии приёмки до написания кода.
- Создадите фронтенд, бэкенд и базу данных.
- Покроете приложение модульными, фронтенд- и интеграционными тестами.
- Контейнеризируете и развернёте его, а также настроите CI/CD с возможностью отката.
- Добавите инструменты наблюдаемости и оповещения о реальных проблемах пользователей вместо графиков загрузки CPU.
- Создадите триггер оповещения.
- Реализуете агента реагирования.

<a id="what-you-can-submit"></a>

## Что можно сдавать

- Собственную идею. Если не знаете, что создать, попросите ИИ помочь с выбором. Небольшой идеи достаточно.
- Любой язык и любой стек. В курсе используется Python, но требования проекта от него не зависят.
- Одно приложение, доведённое до конца. Проект — не четыре отдельных задания. Это одно приложение, для которого вы создаёте спецификацию, пишете код, запускаете его локально, развёртываете и готовите к эксплуатации.
- **Документацию на английском языке, даже если интерфейс на другом языке.** Нельзя рассчитывать, что рецензенты смогут читать на языке интерфейса.
- Около 20 часов работы, распределённых на второй месяц.
- Две попытки. Если не успеете к первому сроку, во второй попытке сдаётся тот же проект по тем же критериям.

<a id="peer-reviewing"></a>

## Взаимное рецензирование

> [!IMPORTANT]
> Взаимное рецензирование — часть проекта, а не дополнительный бонус. Вам нужно оценить три проекта других участников курса. Сдача проекта без рецензирования чужих работ не засчитывается, каким бы хорошим ни был ваш проект.

Рецензирование — ещё и та часть обучения, которая запоминается надолго. В каждом проекте вы разбираетесь, что создано, как это сделано и какие технологии используются, а затем оцениваете его по критериям ниже. Каждый проект немного отличается от остальных, и именно благодаря этим различиям вы узнаёте то, чего не было в курсе.

> [!NOTE]
> Точные сроки и порядок рецензирования указаны на [платформе курса](https://courses.datatalks.club/ai-dev-tools-2026/).

<a id="criteria"></a>

## Критерии

Всего 12 критериев на 24 балла. Для успешной сдачи нужно 10 баллов.

Набирать максимум по каждому критерию необязательно.

<a id="problem-description"></a>

### Описание проблемы

- Проблема не описана. (0 баллов)
- Проблема описана кратко, но непонятно, что делает система или какая функциональность ожидается. (1 балл)
- README ясно описывает проблему, функциональность системы и ожидаемое поведение. (2 балла)

<a id="product-specification"></a>

### Спецификация продукта

- Письменной спецификации нет. (0 баллов)
- Спецификация есть, но нет общедоступного трекера задач. (1 балл)
- Есть спецификация и общедоступный трекер задач. В задачах определены критерии приёмки, и есть подтверждения того, что агенты использовали трекер. (2 балла)

<a id="agent-team-specification"></a>

### Описание команды агентов

- Команда агентов не описана. (0 баллов)
- Роли или агенты упомянуты, но обязанности неясны. (1 балл)
- В проекте определены команда агентов и процесс их совместной работы. (2 балла)

<a id="context-management"></a>

### Управление контекстом

- Документации проекта нет. (0 баллов)
- Есть AGENTS.md или аналогичный файл с описанием проекта. (1 балл)
- Есть AGENTS.md, который также ссылается на модульную документацию о процессе, командах и так далее. (2 балла)

<a id="application"></a>

### Приложение

- Нет работающего приложения либо отсутствует фронтенд, бэкенд или постоянное хранилище. (0 баллов)
- Фронтенд, бэкенд и база данных есть, но соединены не полностью. (1 балл)
- Full-stack-приложение работает целиком: фронтенд взаимодействует с бэкендом, данные сохраняются в базе данных. Приложение запускается локально одной командой. (2 балла)

<a id="testing"></a>

### Тестирование

- Тестов нет или они не запускаются. (0 баллов)
- Есть только модульные либо только интеграционные тесты. (1 балл)
- Есть и модульные, и интеграционные тесты; они запускаются одной командой и проходят успешно. (2 балла)

<a id="containerization"></a>

### Контейнеризация

- Контейнеризации нет. (0 баллов)
- Dockerfile есть, но для запуска всей системы нужны ручные действия. (1 балл)
- Вся система, включая базу данных, работает через Docker или Docker Compose и запускается одной командой. (2 балла)

<a id="deployment"></a>

### Развёртывание

- Приложение не развёрнуто. (0 баллов)
- Шаги развёртывания описаны, но работающее развёртывание не показано. (1 балл)
- Приложение развёрнуто и доступно по общедоступному URL либо есть понятная демонстрация развёрнутого приложения. (2 балла)

<a id="cicd"></a>

### CI/CD

- Конвейера CI/CD нет. (0 баллов)
- CI автоматически запускает тесты для каждого pull request. (1 балл)
- CI запускает тесты, а CD автоматически выполняет развёртывание. (2 балла)
- CI запускает тесты, CD развёртывает приложение в dev, а развёртывание в production выполняется вручную. (3 балла)

<a id="observability"></a>

### Наблюдаемость

- Телеметрии нет. (0 баллов)
- Приложение выдаёт логи, но нет метрик или трассировок либо сигналы нельзя связать с одним запросом. (1 балл)
- Ключевой пользовательский сценарий инструментирован метриками, трассировками и структурированными логами с общим trace ID; данные клиентов и учётные данные не отправляются в телеметрию; сигналы собираются, сохраняются и доступны для просмотра в интерфейсе. (2 балла)

<a id="alerting-on-user-impact"></a>

### Оповещения о влиянии на пользователей

- Оповещений нет. (0 баллов)
- Есть хотя бы одно оповещение. (1 балл)

<a id="on-call-agent"></a>

### Дежурный агент

- Дежурного агента нет. (0 баллов)
- Агент запускается по оповещению и исправляет проблему. (2 балла)
